The 80/20 rule states that 80% of results come from 20% of actions.

It’s the ONE rule you must obey, and this is the most important rule when it comes to mastering system design and passing interviews.

Why?

Because 20% of patterns will help you solve 80% of system design questions.

Let me explain…

Most candidates try to memorize solutions and freeze the moment the interviewer asks them, “Why?” because they know the what, not the why.

PATTERN MATCHING is different:

It’s the ability to understand core concepts, recognize recurring problem types, and map them to proven patterns.

Heuristics:

- Write + Spike: Queue<br/>
- Latency + Global: CDN<br/>
- Load + Growth: Scale Out<br/>
- Read + Bottleneck: Cache<br/>
- Requests + Spike: Throttle<br/>
- Retry + Safety: Idempotent<br/>
- Core + Failure: Redundancy<br/>
- Dataset + Growth: Sharding<br/>
- Text + Search: Inverted Index<br/>
- Upload + Large-file: Chunking<br/>
- Durability + Failure: Replication<br/>
- Broadcast + Realtime: Pub/Sub<br/>
- Location + Search: Geohashing<br/>
- Write + Conflict: Optimistic Lock<br/>
- Untrusted + Execution: Container<br/>
- Realtime + Updates: WebSockets<br/>
- Traffic + Reliability: Load Balancer<br/>
- Distributed + Transaction: Saga pattern<br/>
- Concurrency + Consistency: Row locking<br/>

Interview Questions:

Design a search system: Search engines, Web crawlers
Design a geographical data service: Uber, Yelp, TripAdvisor
Design a social media service: Facebook, Twitter, Snapchat
Design a reservation system: TicketMaster, Booking, Airbnb
Design a location-sharing service: Uber, Google Maps, Zomato

Pattern matching is the 80/20 rule in action.
